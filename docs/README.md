# 视频内容分析桌面应用 — 设计文档

> 调研时间：2026-10-02。除标注外，文中模型价格/规格均来自各厂商官方文档，链接见各文档末尾；落地前请以官网最新为准。

## 项目一句话

Windows + macOS 桌面应用，两阶段交付：**V1 视频分类工具**——导入本地/抖音视频，自动打内容类型标签（分类体系可配置），任务库筛选与统计；**V2 内容分析**——云端转写 + 关键帧 + 多模态大模型，按自定义提示词生成结构化报告（摘要/观点树/章节/待办/金句），对标钉钉 AI 听记与抖音 @豆包，但跨来源、可自定义、可沉淀。全云端模型，不依赖任何本地模型。

## 核心结论速览

1. **技术路线**：默认采用「云端 ASR 转写 + 关键帧截图 → 组装多模态 Prompt → 云端 VLM 结构化输出」的混合管线，而不是把视频直传给模型。原因：国内可直传视频的 API（Qwen3-VL 明确不支持音轨理解，豆包/GLM 文档未提及音频参与）**都不理解视频里的声音**，而抖音内容以口播为主——混合管线不是省钱妥协，而是唯一能保住语音信息的路线。视频直传（Qwen3-VL / GLM-4.6V / GLM-5.3-Flash）作为画面前提类内容的可选路线保留。
2. **模型**：首选 qwen3-vl-flash（阿里百炼，输入 ¥0.15/M token，有免费额度）与 GLM-4.6V-Flash（智谱，免费，已有 bigmodel 账号），备选 doubao-seed-1.6-vision。全部支持 `json_schema` 结构化输出。单条 10 分钟视频分析成本约 **¥0.03–0.2**，可忽略不计。
3. **全云端模型（已拍板，不用本地模型）**：ASR 用阿里百炼 paraformer-v2（¥0.288/小时、句级+词级时间戳、说话人分离、每月赠 10 小时；备选火山 Seed-ASR 2.0 ¥0.8/小时，极速版可直传二进制同步返回）。**不设独立 OCR**——画面内嵌字幕由视觉模型直接从关键帧读取，无解说视频自动加密采样。本地仅保留 ffmpeg 确定性处理（抽音频/截帧/场景检测/phash 去重）。代价：离线不可用、本地文件的音频与帧需上传云端。
4. **桌面架构**：Tauri 2（壳，数 MB）+ React 前端 + Python sidecar（PyInstaller 打包 FastAPI，本地 HTTP + SSE）+ 随应用分发的 ffmpeg（LGPL 构建）。先例：Jan（Electron→Tauri 迁移）、Cap（Tauri+ffmpeg）。
5. **截图频率**：不要固定 1fps。采用「场景切换帧 + 最大间隔兜底 + phash 去重 + 总量上限」四层策略，口播类兜底间隔 5s，10 分钟视频通常收敛到 60–150 帧，长边 768px JPEG。详见文档 03。
6. **节奏（V1 分类 → V2 分析）**：V1 用 CLI 验证分类准确率（top-1 ≥90%）后开发界面，契约只有事件流 + taxonomy 结构；V1 期间并行跑"分析 spike"为 V2 探路（V2 开工前置条件：spike 质量达标），V2 开工前才冻结报告 Schema。
7. **Top 3 风险**：① 抖音风控与 cookie 获取（持续对抗型）；② 分析质量不稳定（靠评测集 + 提示词迭代解）；③ 无解说视频漏内容（靠加密采样 + VLM 直读画面字幕兜底）。下载模块必须隔离成可替换适配器，失败不得影响本地文件链路。
8. **时长上限 20 分钟（仅 V2 分析功能）**：该上限内混合管线单请求可完整处理（最坏约 110K input token），**无需分段 map-reduce**；V1 分类不限时长（抽 10 帧对任意时长可行）；长视频分析列为后续扩展（方案预留见文档 03 §5）。
9. **分类（V1 主功能，V2 兼作价值门控）：VLM 感知 + Jev 决策两层**。感知层（flash 档 VLM）读元数据 + 10 抽样帧（低置信补 30s 音频样本转写），输出英文结构化观察 + 中文证据摘要；决策层用 **Jev（typesafe.ai System One）** 的 Choice 原语出类型 + 概率分布 + 置信度——Jev 只收文本且中文精度较低，故由感知层做中英桥接、Jev 只见英文。**分类体系可配置**：模型只判类型，"哪些类型有价值"由配置映射（改标记即时生效；hint 中文/hint_en 英文分离，后者作为 Jev criteria）。V1 每条视频都出结果、`worthy` 仅作筛选标签；V2 中高置信无价值才跳过分析（fail open），no_value 可改判。Jev 早期访问定价未公开，决策层可切换降级为 VLM 直接分类。详见文档 03 §3.0。
10. **2026-10-02 grill 定稿（两轮 16 问全部确认）**：taxonomy 内置 11 类（新增带货口播；"解说"覆盖游戏/影视解说——有解说归解说）；结果消费 = 站内筛选 + CSV 导出（9 列/UTF-8 BOM/勾选或筛选全量），按类型归档移文件放 V2；本地文件引用原路径（失效可按 hash 重链）、抖音视频原画质直存、删任务连带清理；L2 自动触发（异步不阻塞，"快速模式"可关）；Jev 故障自动降级并标记"降级判定"；云端额度自动按量续费（月预算提醒线 ¥20）；批量按 50–200 条/批、并发 3–5；导入自动去重（file_hash/aweme_id）；分类详情展示感知层 10 帧；Phase 2 直接移植下载签名核心（跳过监视文件夹）。**开工行动项：✅ 全平台 key 已备齐（存项目根 `.env.local`，git 忽略，见文档 04 §4）→ 剩余：① 自选 24 个评测视频用现有 Web 下载器手动下载；② 抖音 cookie 会话有效期至 2026-11-25，Phase 2 前如过期需刷新。**

12. **2026-10-02 第三轮 grill 定稿（D43–D48）**：taxonomy 增加 `name_en` 稳定键（Jev 选项与存储用英文名，中文 name 仅显示，改名不失配）；Jev 预授权降级阈值（>¥0.1/条或 P95>5s → 默认 VLM 直出）；达标分级（≥90% 正式 / 85–90% beta 自用 / <85% 不发布）；OSS V1 默认不启用（不写团队测试桶）；V2 分析模型档为开工前决策项（依据 spike 对比）；应用名 V1 用 `video-tagger` 占位。
13. **2026-10-02 二轮 brainstorm 查漏（D49–D54）**：tasks 表补 `source_meta`（抖音元数据落库，分类证据①与 CSV 依赖）；标注样本库双键（抖音 aweme_id / 本地 file_hash——抖音重下载 hash 会变）；感知层 `observations_en` 半受控 schema（受控枚举 ~20 标签 + free_note），V1 契约从两个扩为**三个**；分类回归报告固定输出（每类 P/R、混淆矩阵、错例清单、L2 触发率、other_guess 聚类）；工程三件套（API 重试指数退避+抖动 / UTC 存储本地显示 / SQLite WAL）；sidecar 本地 HTTP 加一次性 token 握手。
